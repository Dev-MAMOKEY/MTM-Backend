# 착용 이미지는 생성 합성으로 만든다 — 실측 치수 정확도는 유보한다

착용 이미지를 만드는 길은 두 갈래였다. **오려붙이기**는 제품 컷 픽셀을 그대로 쓰고 실측 치수로 크기를
계산하므로 치수가 정확하고 MCM Visetos 모노그램이 훼손되지 않는다. **생성 합성**은 결과가 자연스러울 수
있지만 제품 픽셀이 재생성된다. 서로 다른 렌즈를 준 네 갈래 조사가 각자 다른 근거로 오려붙이기를 가리켰음에도
**생성 합성을 택했다** — 개발자가 이 방식을 이미 시도해 본 경험이 있고, 책상 위 조사가 아니라 실물 결과를
보고 판단하기로 했기 때문이다.

## 이 결정이 무엇을 유보하는가

원 요구사항의 *"제품의 크기 데이터와 사용자의 신체 사이즈에 근거해서 알맞는 비율로"* 는 현재 **보장되지 않는다.**
조사로 확인된 사실: Gemini와 FLUX.2에는 마스크 입력이 아예 없고, 구글의 마스크 인페인팅은 단종됐으며,
OpenAI는 *"마스크는 가이던스이며 정확한 모양을 따르지 않을 수 있다"* 를 자사 문서에 명시한다. 즉 생성 모델에
치수를 강제하는 수단이 API 계층에 존재하지 않는다. 따라서 같은 제품을 두 번 생성하면 크기가 달라지고,
14인치 토트와 11인치 크로스백의 3인치 차이가 화면에 그대로 나타나지 않는다.

## 재평가 조건

첫 착용 이미지가 나오면 **생성된 제품의 크기를 실측 치수와 대조한다.** 어긋남이 서비스의 주장을 무너뜨릴
수준이면 이 ADR을 뒤집고 오려붙이기로 전환한다. 전환에 필요한 조사는 이미 끝나 있다 — 제품 컷의 정면 슬롯은
선언 치수 대비 종횡비가 맞는 것을 고르는 규칙으로 64%가 오차 10% 이내에 들어오고, 나머지 36개 SKU만
사람이 보정하면 된다(반나절).

## 함께 정해진 것

- **정자세 변환 뒤 흰 배경을 지워 배경 제거하는 단계는 넣지 않는다.** 흰옷·밝은 피부가 배경과 함께 지워져
  인물에 구멍이 생긴다. 기준 이미지는 흰 배경인 채로 두고 그 위에 제품을 올린다.
- **백팩은 한쪽 어깨에 걸친 착용 방식으로 그린다.** 정면 정자세에서 등 뒤 백팩은 몸에 가려 보이지 않는다.
- **착용 이미지는 만들 때마다 저장한다.** 생성 결과가 매번 다르기 때문에, 저장하지 않으면 마음에 들었던
  결과를 되찾을 수 없다. 부수 효과로 두 번째 조회부터는 즉시 표시된다.
